## Each run

1. Read the current README and experiment history. Check whether today's task
   was already completed so reruns do not duplicate work.
2. Choose one small or moderate free practice task. Prefer a fresh competition
   when access permits; otherwise finish one useful step in an existing one.
3. Use official training data, a simple baseline, and an appropriate validation
   split. Choose the model from validation results before consulting a new
   leaderboard result.
4. Generate and check the submission format. Aim for one formal submission when
   access and validation support it. Record the actual Kaggle score; clearly
   label unsubmitted experiments and local validation scores.
5. Save reproducible code, source/data hashes, versions, metrics, and a dated
   summary in the relevant competition directory. Preserve earlier results.
6. Commit the day's substantive changes with the verified account identity,
   push to the remote default branch, and verify author attribution.
7. Report the task, short approach, score or reason for no submission, and the
   GitHub commit link. Stop idle Kaggle sessions.

## Working agreements

- No empty, fabricated, backdated, or artificially split commits for graph color.
- No raw competition data, credentials, large model files, or unrelated files.
- No external test labels or repeated leaderboard-based tuning.
- New competition rules and unavailable authentication may require the user.
  Preserve completed work and request the necessary action.
- Keep the scope manageable; do not resume the expensive ARC experiments.
